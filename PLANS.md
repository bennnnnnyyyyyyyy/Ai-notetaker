# Plans and Change Discipline

Before implementing a substantial feature, check the relevant document in [`documentation/plans/`](documentation/plans/). Do not treat an idea, a partial scaffold, or an old chat message as completed functionality.

The status source of truth is [`documentation/plans/checklist.md`](documentation/plans/checklist.md), while completed actions are evidenced in [`documentation/operations/WORKLOG.md`](documentation/operations/WORKLOG.md).

If implementation changes the architecture, update the architecture document and add a worklog entry in the same change. If the work is exploratory, put notes in `documentation/planning/` rather than changing the live architecture description.
